# ClinicStatisticsApp — передаточная документация

Дата актуализации: 21.07.2026.

Этот файл — основной контекст для продолжения разработки в новой задаче. Перед началом работ прочитать его полностью и проверить текущее состояние файлов: проект продолжает активно развиваться.

## 1. Назначение приложения

`ClinicStatisticsApp` — единое настольное WPF-приложение для двух направлений:

1. статистика и управленческие таблицы клиник ЭДКАР;
2. журнал, статистика и рабочие таблицы контакт-центра MANGO OFFICE.

В приложении также есть внутренний чат сотрудников. Это единое окно с вертикальным меню слева, оформленное в стилистике исходного `CallCenterStatisticsApp`.

## 3. Технологии и инфраструктура

- .NET 8, WPF, C#;
- EF Core и Microsoft SQL Server;
- база данных: `ClinicStatisticsDb`;
- сервер БД: `SQL,1433`; при ручной работе с SQL через VPN использовать ожидание подключения не менее 55 секунд;
- внутренний чат: ASP.NET Core Minimal API + SignalR, порт `5088`;
- MANGO OFFICE: REST API ВАТС и Контакт-центра.

Базовая строка подключения задана в:

```text
ClinicStatisticsApp\Data\DbContextFactory.cs
```

Она использует Windows-аутентификацию и `MultipleActiveResultSets=True`.

## 8. Синхронизация MANGO: текущая логика

### Что делают кнопки

- «Обновить» в журнале звонков — импортирует выбранный период и показывает записи.
- «Обновить» в статистике сотрудников/групп — при необходимости импортирует период, затем пересчитывает статистику.
- «Синхронизировать» в «Импорт из Mango» — обновляет справочники (если выбраны флажки) и звонки за период.
- «Обновить расчёт» в локальных рабочих таблицах — получает недостающие данные MANGO и строит таблицу.

Для прошедших дней используется локальный кэш успешной синхронизации. Текущий день всегда обновляется: звонки, записи и тематики могут ещё меняться.

### Ограничение частоты

MANGO может возвращать HTTP 429. В обоих приложениях центральный клиент ограничивает частоту запросов примерно одним запросом в секунду и делает повторные попытки с задержкой.

Не запускать одновременно массовую синхронизацию в `CallCenterStatisticsApp` и `ClinicStatisticsApp`: оба приложения используют один API-ключ, поэтому суммарный поток быстрее достигает лимита MANGO.

### Тематики: важная реализованная особенность

В ответе `/vpbx/cc/call/` MANGO возвращает `tag_id` массивом, например `[10173761]`, а не обязательно строкой. В `MangoApiClient.cs` реализован разбор массива и сопоставление с `CallCenterTopics.MangoTopicId`.

Также проверка принадлежности звонка коллцентру защищена Unicode-escape последовательностями, чтобы кириллица не ломалась при переносе исходников:

- группа `Коллцентр`;
- сотрудник с префиксом `КЦ `;
- `Зоя Ершова`.

Если тематики снова отображаются пустыми, диагностика должна начинаться с SQL-проверки, а не с правок внешнего вида:

```sql
SELECT COUNT(*) AS Calls,
       SUM(CASE WHEN TopicId IS NOT NULL THEN 1 ELSE 0 END) AS CallsWithTopic
FROM CallCenterCalls;
```

Если `CallsWithTopic = 0`, проблема в импорте/разборе API; если число больше нуля, проблема в запросе/биндинге страницы.

### Журнал звонков

- Периоды: быстрые и произвольный.
- Фильтры сотрудников, групп, тематик — множественный выбор с флажками, пунктами «Все» и «Без».
- При выборе группы «Коллцентр» должны автоматически выбираться и показываться сотрудники коллцентра: имена с `КЦ ` и Зоя Ершова.
- Повторяющиеся сотрудники в фильтре недопустимы.
- Двойной щелчок по строке открывает карточку звонка.
- Нижняя строка «Всего» всегда остаётся внизу и не участвует в сортировке как обычный звонок.

### Статистика сотрудников и групп

- Содержит периоды, время «от/до», фильтры сотрудников/групп/тематик.
- По умолчанию для коллцентра выбрана группа «Коллцентр».
- Строка «Всего» закреплена внизу независимо от сортировки.
- Сотрудники «КЦ …» и Зоя Ершова входят в состав коллцентра, даже если у них нулевые показатели.

### Рабочие таблицы («Гугл-таблички»)

Внутри используются вкладки:

- «Отчёты»: показатели по дням, ПЕРК по клиникам, графики и отсутствия;
- «Сводные»: месячные сводные, КЭФ, ручные поля и оценочные таблицы.

Принципы:

- автоматические показатели строятся по журналу звонков и тематикам;
- графики, отпуска, отгулы и часть управленческих столбцов остаются ручными;
- столбцы клиник имеют объединённые заголовки «ПЕРК/ПЛАН»;
- цветовые блоки клиник чередуются в серо-голубо-синей гамме;
- итоги по столбцам и строка «ПЕРК+ПЛАН» находятся внизу;
- числа центрируются, ФИО выравниваются по левому краю.

## 10. Внешний вид и правила переноса интерфейса

Эталон интерфейса коллцентра — `CallCenterStatisticsApp`, а не первоначальный вид `ClinicStatisticsApp`.

При доработке:

1. переносить XAML, code-behind, глобальные стили, шаблоны кнопок, комбобоксов, флажков и `DataGrid` из эталона;
2. не заменять их произвольными стандартными WPF-контролами или «похожим» стилем;
3. сохранять размеры, отступы, границы, поведение выпадающих множественных фильтров и ширину колонок;
4. при переносе менять только пространства имён и модели/сервисы целевого приложения.

Во всех длительных операциях должен использоваться единый busy-overlay с текстом текущего шага. Сообщение «готово» нельзя показывать до фактического окончания операции.

Для защиты от штатной отмены загрузки при навигации в `App.xaml.cs` обоих приложений добавлен обработчик `DispatcherUnhandledException`, который игнорирует только `OperationCanceledException`. Другие ошибки не скрываются.

## 13. Возможное развитие: рабочее место оператора

Идея отложена до уточнения тарифа MANGO: сделать локальную панель оператора, в которой тематика сохраняется в SQL сразу после звонка по `entry_id`.

Рекомендуемый подход — не создавать свой SIP-софтфон с нуля, а использовать MANGO Talker/текущую телефонию для звука и добавить в приложение:

1. получение событий через API «сервер–клиент» MANGO/WebSocket;
2. карточку активного звонка;
3. моментальное локальное присвоение тематики;
4. фоновую сверку с MANGO для записи разговора и истории;
5. при необходимости — команды инициирования/перевода через API.

Перед реализацией уточнить у MANGO: включён ли API «сервер–клиент» и WebSocket в действующий тариф, а также доступна ли запись тематики через API Контакт-центра.

## 16. Проверочный список после изменений

После каждой доработки:

1. собрать Release-конфигурацию;
2. проверить вход как минимум под `Admin`, `CallCenter` и `Statistics`;
3. убедиться, что чат открывается для любой роли;
4. проверить, что роли не видят запрещённые разделы;
5. для изменений MANGO проверить малый период и отсутствие HTTP 429;
6. для тематик проверить запись с известным тегом, затем SQL-счётчик `CallsWithTopic`;
7. для UI коллцентра визуально сравнить результат с `CallCenterStatisticsApp`;
8. не перезаписывать пользовательские локальные настройки и не удалять чужие изменения в рабочем дереве.

## 17. Известные ограничения и технический долг

- В медицинском модуле Release-сборка имеет несколько старых предупреждений nullable (`CS8602`), не связанных с модулем коллцентра. Ошибок сборки нет.
- Полноценные вебхуки MANGO пока не используются из-за стоимости услуги.
- Тематики при REST-режиме могут появляться позже завершения звонка; текущий день всегда синхронизируется повторно.
- Массовая параллельная синхронизация обоих приложений одним ключом MANGO может вызвать HTTP 429.
- Аутентификация требует отдельного безопасного перехода на хеширование паролей.
- Для внешнего доступа к чату и вебхукам пока не требуется публичный хостинг; чат рассчитан на локальную сеть.

## 19. Модуль задач

### Назначение и доступ

В приложении реализован внутренний модуль задач, доступный всем авторизованным пользователям. Пункт **«Задачи»** расположен в левом меню главного окна и открывает `ClinicStatisticsApp.UI\Views\TasksPage.xaml`.

Обычный пользователь видит задачи, которые он создал или на которые назначен ответственным. Администратор видит все задачи. В фильтре области можно переключаться между всеми доступными задачами, поставленными пользователем и назначенными пользователю.

Автор задачи может менять постановку: название, описание, ответственного, приоритет, срок и чек-лист. Исполнитель может менять статус, оставлять комментарии и указывать результат выполнения; он не может незаметно изменить исходную постановку.

### Статусы и контроль исполнения

Поддерживаются статусы: `New` — новая, `InProgress` — в работе, `Paused` — на паузе, `Review` — на проверке и `Done` — завершена.

Доска группирует задачи по статусам. Доступны фильтры по статусу, включая «Просрочены», а также по авторству/назначению. Карточка показывает приоритет, срок, прогресс чек-листа, комментарии, результат завершения и длительность текущего статуса.

У каждой задачи есть журнал этапов: время перехода в каждый статус, время выхода и пользователь, выполнивший изменение. Экран задачи рассчитывает время первого старта, суммарное время в `InProgress`, количество и интервалы пауз, завершение и результат. Исполнитель оставляет комментарии/отчёты в карточке.

### Уведомления

Кнопка «Уведомления» показывает непрочитанные сообщения и последние 50 уведомлений. Они создаются при назначении/переназначении, новом комментарии и первом обнаружении просрочки. Просрочки проверяются при обновлении раздела; после открытия центра уведомлений они отмечаются прочитанными.

### Код модуля

| Файл | Назначение |
|---|---|
| `ClinicStatisticsApp\Models\WorkTask.cs` | Сущности задачи, чек-листа, комментариев, истории статусов и уведомлений. |
| `ClinicStatisticsApp\Services\WorkTaskService.cs` | Права доступа, CRUD, журнал этапов, комментарии, просрочки и уведомления. |
| `ClinicStatisticsApp.UI\Views\TasksPage.xaml(.cs)` | Доска, фильтры и карточки задач. |
| `ClinicStatisticsApp.UI\Views\TaskEditorWindow.cs` | Карточка задачи, чек-лист, комментарии и история выполнения. |
| `ClinicStatisticsApp.UI\Views\TaskNotificationsWindow.cs` | Центр уведомлений задач. |

### База данных и порядок обновления

Модуль использует `WorkTasks`, `WorkTaskChecklistItems`, `WorkTaskComments`, `WorkTaskStatusHistory`, `WorkTaskNotifications`.

Скрипты выполняются в порядке: `007_CreateWorkTasks.sql`, `008_AddWorkTaskTracking.sql`, `009_AddWorkTaskCompletionResult.sql`, `010_AddWorkTaskNotifications.sql`.

`011_UpsertAntoninaGarbuzova.sql` создаёт или обновляет учётную запись Антонины Гарбузовой с ролью `Admin`, активным статусом и без привязки к филиалу. Пароль не приводится в документации.

SQL Server приложения доступен как `SQL,1433`. При соединении через VPN возможна задержка: для применения SQL-скриптов и диагностики используйте увеличенный таймаут подключения не менее 55 секунд. Не считать первоначальную задержку VPN признаком недоступности базы.

### Проверка модуля задач

1. Создать задачу с исполнителем и сроком.
2. Под исполнителем перевести её в «В работе», добавить комментарий, поставить на паузу, возобновить и завершить с результатом.
3. Под автором проверить историю выполнения: старт, суммарное рабочее время, паузы, завершение и результат.
4. Проверить фильтры «Поставленные мной», «Назначенные мне», «На паузе», «Готово» и «Просрочены», а также уведомления о назначении и комментариях.

## 20. Календарь и почта

### Календарь

Страница `ClinicStatisticsApp.UI\Views\CalendarPage.xaml(.cs)` доступна всем авторизованным пользователям. Она поддерживает дневной, недельный, месячный и годовой виды, создание по свободной ячейке и переход к выбранной дате.

Карточка события находится в `CalendarEventWindow.xaml(.cs)`. У события есть название, описание, время, весь день, цвет, приглашённые участники, повторение (`None`, `Daily`, `Weekly`, `Monthly`) и напоминание. Напоминания проверяются на клиенте каждые 30 секунд, поэтому приложение должно быть запущено. Событие видят автор и приглашённые участники. Изменение и удаление доступны автору; полный доступ к чужим событиям предусмотрен только для пользователя, указанного в текущем коде календаря как управляющий всеми событиями.

Изменения схемы календаря расположены в `Database\004_CreateCalendarEvents.sql`, `005_CreateCalendarEventParticipants.sql`, `006_AddCalendarRecurrenceAndReminders.sql`.

### Почта

Страницы `MailPage.xaml(.cs)` и `MailSettingsPage.xaml(.cs)` дают пользователю доступ к его почтовому ящику. Настройки почты сохраняются отдельно для каждого пользователя, не попадают в общий файл приложения и не должны публиковаться в Git.

Функции: папки, поиск по отправителю/теме, чтение писем, вложения, создание и отправка сообщений, обновление вручную и фоновое обновление входящих раз в две минуты. Используются `MailKit`, `MailSettingsStore`, `MailFilterStore` и `MailFolderCache`. Перед первым использованием пользователь должен заполнить «Настройки → Настройки почты».
